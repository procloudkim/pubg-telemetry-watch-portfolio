# 021 — SQL 문서 소유권과 후속 리팩터링

- Why: SQL 실행 위치·정적 구문·업무 계약이 섞이면 누락과 중복 소유를 구분하기 어렵다.
- What: 사용자 승인에 따라 배치·검토·연구 audit·검증의 문서 트리를 만들고 계약을 한 소유 문서에만 배정한다.
- How: owners.json의 완전·배타 분할, 계약 필드, source inventory를 CI에서 검사한다.
- How: draw.io/SVG/PDF에 실제 구조·보안 경계·문서 소유권을 연결한다.
- Trade-off: 실행 SQL과 기존 runtime 폴더는 이번에 이동하지 않는다; 사용자 지시대로 전체 리팩터링은 별도 후속 계획이다.
- Trade-off: AST는 새 wrapper의 의미를 자동 증명하지 않으므로 미할당 실행 지점은 거부하고 수동 계약 검토를 요구한다.
