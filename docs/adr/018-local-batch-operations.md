# 018 — 로컬 배치 실행과 SQL 검산
Why: 프로세스 종료 시 호출 예산 누락과 SQL NULL 통과를 확인했고, 재처리의 복구 경계를 명시할 필요가 있다.
What: 사용자 승인(2026-09-09)에 따라 단일 Linux/WSL Worker, 영속 SQLite, CLI와 SQL 리포트를 도입한다.
How: 요청 전 예약 원장; 작업별 이벤트·결과·성공 상태의 단일 트랜잭션; 실패와 재시도 이력; 고정 입력 해시.
How: 기존 파서·룰을 재사용하고 원시 공격·피해 투영의 SQL 계산을 Python과 비교한 뒤 발행한다.
How: 프로세스 중단·중복·손상 입력·NULL 반례, 합성 게이트, 동결 해시와 1M/10M 부하를 검증한다.
Trade-off: SQLite 단일 작성자는 로컬 복구 증거에 충분하며 분산 처리량과 실제 서비스 운영을 입증하지 않는다.
기각: 별도 웹/API·분산 큐·새 프레임워크는 현재 실행 흐름에 불필요하다. 필요 시 독립 설계한다.
경계: 신규 API 수집·룰 변경·외부 정확도 주장은 없고 기존 연구 산출물은 보존한다.
