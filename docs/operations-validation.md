## 측정 조건

같은 WSL 호스트와 Python 3.11.15 / SQLite 3.50.4, seed 20260909, 100 synthetic actors/match, 60% 위치·20% 공격·20% 피해 workload를 사용했다. 입력과 DB는 Linux 파일시스템이다. source 사본도 Linux 경로로 고정했다. 주변 호스트 부하는 통제하지 못했다.

입력군별 준비 실행 1회 + 측정 3회, 매회 새 프로세스·새 DB다. 각 버전 16회, 총 32회다. 생성·정합 비교 시간은 제외한다. `run+report`가 처리량 분모, E2E는 run 시작부터 report 종료까지다. RSS는 GNU Time `%M`으로 각 프로세스 종료까지 측정하며 run/report를 합산하지 않는다. p50/p95는 성공 commit 직후까지의 처리 지연이고 p95는 nearest-rank, n은 해당 반복의 매치 수다. 커밋 후 계측 저장 전 종료는 NULL로 유지한다.

| 소스 | fingerprint |
|---|---|
| Baseline | `7dbb3688f3c364caff0d6917d24f849760b742c59ef617b682b61978824115e1` |
| Review 구현 | `1e098cee0361245f52cd18b7fe8e9e8767f562068229309a3a0232690c26d3b4` |

기존 운영 key는 코드/runtime을 포함한 job ID에 의존한다. 같은 버전의 반복은 결과 hash가 같고, 버전 간 비교는 합성 actor ID로 대응한 룰·건수·근거가 일치했다. float만 기존 SQL parity의 상대/절대 1e-9를 적용했다. 각 입력군의 manifest hash와 generator hash도 버전 간 동일하다.

## 복구·한계·재현

합성 시연의 commit 전 종료 코드는 37, 다음 run의 복구 소요 시간은 0.866초였다. INTERRUPTED 이력 후 1회 성공했으며 이미 완료한 검토 case의 메모·상태는 유지됐다. 백업은 integrity/FK·전체 SQL dump·검토 이력·재발행 보고서 비교를 통과했다.

오프라인 사전 검사에서는 sysfs에 이전 namespace 인터페이스가 보이는 검사 오류가 있었다. 동일 unshare 안에서 socket 인터페이스를 직접 확인하도록 검사 코드를 고친 뒤 전체 gate를 통과했다. 실패를 생략하거나 다른 격리 방식으로 대체하지 않았다.

[실행 절차](operations-runbook.md), [SQL 계약·전수 목록](sql/README.md), [15개 아키텍처 원본/exports](architecture/operations.md), [결정 ADR 019](adr/019-measured-review-operations.md)를 함께 본다. 기준선 재현은 최종 코드가 아니라 보존된 `baseline-source/` 사본에서 실행해야 한다. 현재 코드는 review 버전이다.

SQL은 배치·검토·연구 audit·검증으로 나눠 20개 계약을 배타적으로 관리한다. 87개 실행 지점·20개 helper 호출·117개 고유 정적 텍스트는 서로 다른 집계 단위다. [보안 경계와 검사](security/operations.md)를 문서화했고, 저장소 전체 책임 분리는 사용자 지시대로 [후속 리팩터링 계획](maintenance/refactoring-plan.md)에 남겼다.

원자료·baseline/feature 소스·실행 명령·개별 attempt·query plan·입력·backup은 로컬 `private/runs/20261027/` 증거 묶음에 보존한다. 이 경로는 Git 비추적이며 clone으로 복원되지 않는다. 묶음의 SHA 목록과 실제 복원 결과는 `bundle-verification.json`에서 확인한다. 비밀정보·원 연구 telemetry는 포함하지 않는다.

최종 묶음은 250,590,367 bytes이며 새 로컬 경로로 복원한 964개 파일 SHA가 모두 일치했다. SQLite integrity `ok`, FK 오류 0, 전체 dump·검토 이력 8행·재발행 report byte 동일을 확인했다. runtime은 버전 manifest로 보존했으며 OS/VM image나 독립 외부 백업을 확보한 것은 아니다. 작업 브랜치 변경은 미커밋 상태다.
