# 리팩터링 전후 합성 성능

## 성능 비교

고정 seed 20260909, 동일 Python/SQLite·CPU·affinity·파일시스템과 입력 manifest SHA를 사용했다.
각 입력군은 준비 1회와 측정 3회이며 총 32회다. 매번 새 DB·프로세스에서 run/report를 GNU Time으로
측정했다. 입력 생성·actor 비교는 측정 시간에서 제외한다. 워밍업을 포함한 개별 값은 아래에 남긴다.

모든 같은 버전 반복에서 결과 hash가 일치했고 버전 간에는 합성 actor 대응 결과가 통과했다.
룰·건수·근거는 정확 비교하고 float만 상대/절대 1e-9를 허용했다. 실패·재시도는 0회다.
관측 처리 시간과 RSS는 감소했다. 하지만 전후 실행 순서를 교차 무작위화하지 않았고 host의 다른
활동·cache·스케줄링을 완전히 통제하지 않았으므로 이 차이를 리팩터링만의 인과 효과로 확정하지 않는다.
새 인덱스·탐지 최적화는 적용하지 않았다. 매치 최대 크기가 커지면 peak RSS도 증가한다.
공유 CI 성능 SLO, 실제 서비스 처리량 또는 탐지 정확도 추정으로 사용하지 않는다.

실행 환경: `{"platform": "Linux-6.18.33.2-microsoft-standard-WSL2-x86_64-with-glibc2.39", "python": "3.11.15", "sqlite": "3.50.4"}`.
CPU: `AMD RYZEN AI MAX+ 392 w/ Radeon 8060S`; CPU affinity와 GNU Time 버전은 원시 JSON에 보존했다.

원시 JSON·요약·명령·결과·실행계획은 로컬 `private/refactoring/20261027/{before,after}*/`에 있다.
보고서용 반올림값이 아니라 원시 반복값을 비교 정본으로 사용한다.

```bash
python -m src.ops_demo --output /tmp/watch-before --sizes 1000000 10000000 --repeats 3
# 별도 보존한 변경 후 소스에서 실행
python -m src.ops_demo --output /tmp/watch-after --sizes 1000000 10000000 --repeats 3 --compare-to /tmp/watch-before
# 각 revision에서 별도 새 output으로 --sizes 1000000 --match-events 100000/200000 반복
```

각 revision의 소스 사본을 보존하고 같은 Python/SQLite runtime으로 실행한다. 기존 output 재사용은 거부한다.
전체 절차는 [운영 재현](../operations-runbook.md), 코드 경계는 [아키텍처](../architecture/clean-architecture.md)를 따른다.
